# GasGuard v2 — ระบบตรวจจับแก๊สรั่ว

เว็บแอปเฝ้าระวังแก๊สรั่วแบบเรียลไทม์ · ใช้งานได้จริงทั้งโหมดจำลองและต่อเซ็นเซอร์จริง
รองรับมือถือ / ไอแพด / คอมพิวเตอร์ · ติดตั้งเป็นแอปได้ (PWA) · ทำงานออฟไลน์ได้

---

## เริ่มใช้งานใน 30 วินาที

1. เปิดไฟล์ `index.html` (หรือรัน `npx http-server . -p 8080` แล้วเปิด `http://localhost:8080`)
2. ใส่ PIN เริ่มต้น **1234**
3. ระบบเริ่มทำงานในโหมดจำลองทันที — เปลี่ยน PIN ได้ที่ **ตั้งค่า → ทั่วไป**

> เปิดจากไฟล์ตรง ๆ (`file://`) ใช้ได้ แต่ Service Worker/ติดตั้งเป็นแอปจะไม่ทำงาน
> แนะนำให้เปิดผ่าน http/https

---

## นำขึ้น Netlify

**วิธีที่ 1 — ลากวาง (ง่ายสุด)**
เข้า [app.netlify.com/drop](https://app.netlify.com/drop) แล้วลากโฟลเดอร์นี้ (หรือไฟล์ zip) ลงไป เสร็จภายในไม่กี่วินาที

**วิธีที่ 2 — ผูกกับ GitHub**
push โฟลเดอร์นี้ขึ้น repo แล้วเชื่อมกับ Netlify
ไฟล์ `netlify.toml` ตั้งค่าไว้แล้ว: publish = `.` , ไม่มี build command

หลัง deploy เว็บจะเป็น HTTPS ซึ่งจำเป็นสำหรับการแจ้งเตือนและติดตั้งเป็นแอป

## เชื่อมต่อบัญชีผู้ใช้ + ฐานข้อมูลจริง (ฟรี ไม่ต้องใช้บัตรเครดิต)

ค่าเริ่มต้นของ GasGuard ใช้ **โหมด PIN ออฟไลน์** — ข้อมูลเก็บอยู่ในเบราว์เซอร์เครื่องเดียวเท่านั้น
ถ้าอยากให้ผู้ใช้ **สมัครสมาชิกด้วยอีเมลจริง** และให้ข้อมูลเซ็นเซอร์/ประวัติแจ้งเตือน **ซิงก์ข้ามอุปกรณ์ได้**
ให้เชื่อมกับ [Supabase](https://supabase.com) ซึ่งมีแพ็กเกจฟรีที่รองรับงานนี้ได้สบาย (500MB ฐานข้อมูล, ผู้ใช้ล็อกอินได้ถึง 50,000 คน/เดือน)

**ขั้นตอน (ใช้เวลา ~5 นาที):**

1. ไปที่ [supabase.com](https://supabase.com) → **Start your project** → สมัครฟรีด้วย GitHub หรืออีเมล (ไม่ต้องใช้บัตรเครดิต)
2. กด **New project** ตั้งชื่อโปรเจกต์ ตั้งรหัสผ่านฐานข้อมูล (เก็บไว้ดี ๆ) เลือก Region ใกล้ไทยที่สุด (เช่น Singapore) แล้วรอสร้างโปรเจกต์ประมาณ 1-2 นาที
3. เมื่อโปรเจกต์พร้อม ไปที่เมนู **SQL Editor** (แถบซ้าย) → **New query**
4. เปิดไฟล์ `supabase/schema.sql` ที่แนบมาในโปรเจกต์นี้ คัดลอกทั้งหมดไปวางในช่อง SQL Editor แล้วกด **Run**
   (คำสั่งนี้จะสร้างตารางเซ็นเซอร์/ประวัติแจ้งเตือน พร้อมตั้งค่าความปลอดภัยแบบ Row Level Security ให้อัตโนมัติ)
5. ไปที่ **Project Settings** (ไอคอนเฟือง) → **API** → คัดลอกค่า 2 ตัว:
   - **Project URL**
   - **anon public** key
6. เปิดไฟล์ `js/config.js` ในโปรเจกต์ แล้ววางค่าทั้งสองแทนที่ `YOUR-PROJECT.supabase.co` และ `YOUR-ANON-PUBLIC-KEY`
7. บันทึกไฟล์ → commit → push ขึ้น GitHub → Netlify จะ deploy เวอร์ชันใหม่ให้อัตโนมัติ

เท่านี้หน้า Login จะเปลี่ยนจากโหมด PIN เป็นแท็บ **"เข้าสู่ระบบ" / "สมัครสมาชิก"** ด้วยอีเมลจริงทันที
(ผู้ใช้ที่ยังไม่ได้ทำขั้นตอนนี้จะเห็นโหมด PIN ออฟไลน์เหมือนเดิม แอปไม่พังแน่นอน)

> **หมายเหตุด้านความปลอดภัย:** ค่า `anon public key` ปลอดภัยที่จะฝังในโค้ดฝั่งหน้าเว็บ (เป็นแนวทางมาตรฐานของ Supabase)
> เพราะการเข้าถึงข้อมูลจริงถูกจำกัดด้วย **Row Level Security** ที่ตั้งไว้ใน `schema.sql` — ผู้ใช้แต่ละคนเห็นได้แค่ข้อมูลของตัวเองเท่านั้น
> **ห้ามคัดลอกค่า `service_role key`** (อีกค่าหนึ่งในหน้าเดียวกัน) มาใส่ในโค้ดฝั่งหน้าเว็บเด็ดขาด เพราะเป็นคีย์สิทธิ์สูงสุดที่ข้ามการป้องกันทั้งหมด

**ค่าเริ่มต้นฟรีของ Supabase ครอบคลุมแค่ไหน:** ฐานข้อมูล 500MB, ผู้ใช้ล็อกอิน (MAU) 50,000 คน/เดือน, พื้นที่ไฟล์ 1GB —
เพียงพอสำหรับโปรเจกต์นักศึกษา/เดโมสบาย ๆ ข้อควรรู้อย่างเดียวคือถ้าไม่มีการใช้งานเลยติดต่อกัน 7 วัน โปรเจกต์ฟรีจะ "พัก" ชั่วคราว
(กู้คืนได้ในหน้า Dashboard ภายใน 1 คลิก ข้อมูลไม่หาย) — ถ้าใช้งานเดโมบ่อย ๆ ไม่ต้องกังวลเรื่องนี้

## โครงสร้างไฟล์

```
index.html              หน้าเว็บหลัก (ทุกหน้าอยู่ในไฟล์เดียว)
css/style.css           ธีมมืด/สว่าง + responsive ทุกขนาดจอ
js/config.js            ค่าเชื่อมต่อ Supabase (ใส่ URL/anon key ที่นี่)
js/store.js             ข้อมูลกลาง + บันทึกลง localStorage
js/auth.js              สมัครสมาชิก/เข้าสู่ระบบด้วยอีเมล (Supabase Auth)
js/db.js                ซิงก์เซ็นเซอร์/ประวัติแจ้งเตือนกับฐานข้อมูลคลาวด์
js/sources.js           แหล่งข้อมูล: จำลอง / REST API / MQTT
js/alerts.js            เอนจินแจ้งเตือน + เสียงไซเรน + notification
js/charts.js            กราฟทั้งหมด (Chart.js)
js/ui.js                การแสดงผลและฟอร์มทุกหน้า
js/app.js               เริ่มระบบ + ล็อกอิน + PWA
sw.js                   Service Worker (ออฟไลน์)
manifest.webmanifest    ข้อมูลแอปสำหรับติดตั้งบนมือถือ
vendor/                 Chart.js + Font Awesome + Supabase client (ติดมาในเครื่อง ใช้ออฟไลน์ได้)
supabase/schema.sql     คำสั่งสร้างตารางฐานข้อมูล + Row Level Security (รันใน Supabase SQL Editor)
icons/                  ไอคอนแอป
firmware/               โค้ดตัวอย่าง ESP32 สำหรับต่อเซ็นเซอร์จริง
server/                 เซิร์ฟเวอร์ตัวอย่างสำหรับโหมด REST API (ทางเลือก)
netlify.toml            ตั้งค่า deploy
```

## ฟีเจอร์

| หน้า | ทำอะไรได้ |
|---|---|
| แดชบอร์ด | KPI สรุป, การ์ดทุกเซ็นเซอร์, เกจค่าเฉลี่ย, กราฟย้อนหลัง 24 ชม. |
| ตรวจวัดเรียลไทม์ | กราฟสด หยุด/เล่นได้, เปรียบเทียบรายโซน, อุณหภูมิ/ความชื้น |
| การแจ้งเตือน | ระดับเตือนตามเกณฑ์จริง, รายการแจ้งเตือน, ปุ่มทดสอบระบบ |
| สถิติ | ค่าเฉลี่ย/สูงสุดรายวัน, สัดส่วนเวลาแต่ละระดับ, ดัชนีความปลอดภัย, ส่งออก CSV |
| ประวัติเหตุการณ์ | ค้นหา + กรองตามระดับ/เซ็นเซอร์/ช่วงเวลา, ส่งออก CSV |
| จัดการเซ็นเซอร์ | เพิ่ม/แก้ไข/ลบเซ็นเซอร์เอง, ตั้งเกณฑ์เฉพาะตัว, ค่าชดเชยการสอบเทียบ |
| ตั้งค่า | แหล่งข้อมูล, เกณฑ์เตือน, เสียง/การแจ้งเตือน, ธีม, PIN, สำรอง/กู้คืนข้อมูล |

**ระบบที่ทำงานเบื้องหลัง**

- สมัครสมาชิก/เข้าสู่ระบบด้วยอีเมลจริง (Supabase Auth) พร้อมลืมรหัสผ่านทางอีเมล — ใช้งานได้เมื่อเชื่อมต่อฐานข้อมูลตามขั้นตอนด้านบน ไม่งั้นจะใช้โหมด PIN ออฟไลน์แทนโดยอัตโนมัติ
- เซ็นเซอร์และประวัติแจ้งเตือนซิงก์ขึ้นฐานข้อมูลคลาวด์ต่อผู้ใช้ 1 คน (แยกข้อมูลกันด้วย Row Level Security) — เข้าดูจากอุปกรณ์ไหนก็เห็นข้อมูลชุดเดียวกัน
- เอนจินแจ้งเตือนแบบมีเงื่อนไขจริง: ต้องอ่านค่าเกินเกณฑ์ติดต่อกัน N ครั้ง (กันสัญญาณรบกวน) และมีช่วงหน่วงกลับ (hysteresis) กันเตือนกระพริบ
- เสียงไซเรนสังเคราะห์ด้วย Web Audio (ไม่ต้องมีไฟล์เสียง) + สั่นเครื่อง + แจ้งเตือนระบบ + ป๊อปอัพขั้นตอนฉุกเฉิน
- ตรวจจับเซ็นเซอร์ขาดการติดต่อ แล้วเปลี่ยนสถานะเป็น "ออฟไลน์"
- เก็บข้อมูลย้อนหลัง 24 ชม. และสรุปรายวัน 45 วัน ไว้ในเครื่อง (localStorage)
- Webhook ส่งต่อเหตุการณ์ไป LINE Notify / Discord / n8n ได้
- ล็อกอินด้วย PIN (แฮชด้วย SHA-256) — เป็นการล็อกหน้าจอฝั่งผู้ใช้ ไม่ใช่ระบบความปลอดภัยระดับเซิร์ฟเวอร์

## ต่อเซ็นเซอร์จริง

รูปแบบข้อมูลที่เว็บรับได้ (ยืดหยุ่น — ใช้ `id`/`deviceId`, `ppm`/`value` ก็ได้):

```json
{ "id": "kitchen-01", "ppm": 142, "temp": 31.5, "humidity": 62 }
```

`id` ต้องตรงกับ **รหัสอุปกรณ์** ในหน้าจัดการเซ็นเซอร์
ถ้าส่ง id ที่ยังไม่มีในระบบ เว็บจะเพิ่มเซ็นเซอร์ให้อัตโนมัติ แล้วค่อยแก้ชื่อ/ตำแหน่งทีหลังได้

### วิธี A — MQTT (แนะนำเมื่อ deploy บน Netlify)

ตั้งค่าใน **ตั้งค่า → แหล่งข้อมูล → MQTT**

- Broker URL: `wss://broker.hivemq.com:8884/mqtt` (ทดลองฟรี) — ต้องเป็น `wss://`
- Topic: `gasguard/+/reading`

ฝั่ง ESP32 publish ไปที่ `gasguard/<device-id>/reading` (ดู `firmware/gasguard_esp32.ino`)

### วิธี B — REST API

ตั้งค่าใน **ตั้งค่า → แหล่งข้อมูล → REST API** โดยใส่ URL ที่คืนค่า JSON ของทุกเซ็นเซอร์
ใช้เซิร์ฟเวอร์ตัวอย่างใน `server/` ได้ทันที (`node server.js`) — อ่านรายละเอียดใน `server/README.md`

> ข้อควรระวัง: เว็บบน Netlify เป็น HTTPS จึงเรียก API ที่เป็น `http://` ไม่ได้
> ให้ใช้ MQTT over wss หรือนำเซิร์ฟเวอร์ขึ้นโฮสต์ที่มี HTTPS

## ติดตั้งเป็นแอปบนมือถือ/ไอแพด

- **iPhone / iPad**: เปิดใน Safari → ปุ่มแชร์ → "เพิ่มไปยังหน้าจอโฮม"
  (การแจ้งเตือนของ iOS ทำงานเฉพาะเมื่อเพิ่มลงหน้าจอโฮมแล้ว)
- **Android**: Chrome → เมนู → "ติดตั้งแอป"
- **Windows/Mac**: ปุ่มติดตั้งในแถบ URL หรือปุ่มในหน้าคู่มือ/ตั้งค่า

## ข้อควรทราบด้านความปลอดภัย

ระบบนี้เป็นเครื่องมือช่วยเฝ้าระวังและสื่อการเรียนรู้ **ไม่ใช่อุปกรณ์นิรภัยที่ผ่านการรับรอง**
ห้ามใช้แทนเครื่องตรวจจับแก๊สมาตรฐานในพื้นที่เสี่ยง และควรมีระบบตัดแก๊ส/ระบายอากาศสำรองเสมอ
